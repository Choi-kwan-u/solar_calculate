> 구현하면서 바뀐 점(세금 계수, 보조금 3kW 한도, NASA POWER 기간·해상도 등)은 [README의 "설계 문서와 다른 점"](../README.md#설계-문서와-다른-점) 참고. 아래는 받은 설계 문서 원문이다.

# 태양광 손익분기 계산기 — 기획/설계 문서

> 위치 검색 → 패널 개수·1장 가격·월 전기요금 입력 → 하루/한 달/1년 발전량(kWh)·절감액(원)과 손익분기 일수(범위)를 한 화면에서 바로 보여주는 정적 웹사이트.
> 광고·회원가입·수익화 없음. 계산기 하나로 끝나는 사이트.

## 0. 결론 먼저

| 질문 | 답 |
|---|---|
| LLM 필요한가? | **아니오.** 입력이 전부 구조화된 값(숫자·선택지)이고 출력은 사칙연산 결과라 결정론적 계산이면 충분하다. LLM을 끼우면 비용·지연·비결정성(같은 입력에 다른 숫자)·숫자 환각만 생긴다. |
| 그럼 쉬운 프로젝트인가? | 계산식 자체는 쉽다. **어려운 건 데이터 쪽 세 가지**: ① 위치→일사량 매핑, ② 전기요금이 누진제라 "kWh당 단가"가 상수가 아님, ③ 패널 와트수·방향·성능비 같은 가정이 결과를 ±20% 흔든다. |
| 설계 원칙 | 모든 상수를 화면에 드러내고(접이식 "계산 근거" 패널) 사용자가 바꿀 수 있게 한다. 숫자가 틀려 보여도 "왜 그렇게 나왔는지"가 보이면 신뢰가 유지된다. |
| 결과 숫자의 의미 | **발전량(kWh)과 절감액(원)을 나란히 보여준다.** 발전량은 위치·패널·방향·그늘로 정해지는 물리량이고, 돈은 '수익'이 아니라 '절감액'이다. 10kW 이하 주택용은 상계거래라 남는 전기를 현금으로 받지 못한다. |
| 결과를 가장 크게 흔드는 변수 | **그 집의 전기 사용량.** 같은 패널 7장이 월 150kWh 집에서는 손익분기 19년, 550kWh 집에서는 5년(3.2). 그늘(±15~35%)보다 훨씬 크다 → 월 전기요금 입력을 첫 화면에 둔다. |
| 그늘·방향을 모르는 사용자 | "없음"이 아니라 **"모름"을 기본 선택**으로 둔다. "없음"은 최선값이라 모르는 사람이 누르면 손익분기가 짧게 찍힌다. "모름"은 중간값 + 넓은 범위. |

## 1. 사용자 흐름

```
[위치 검색]    "서울 중구"  ──▶ 일사량 조회(연평균 + 월별 12개)
[패널 개수]    7장 (슬라이더 1~40)
[1장당 가격]   750,000원 (기본값 채워져 있고 수정 가능)
[월 전기요금]  71,500원 (선택·강력 권장) ──▶ "≈ 월 350kWh 사용" 역산 표시
 ▸ 더 정확하게:  지붕 방향 [모름|남|동·서|북|평지붕]   그늘 [모름|없음|조금|많음]
                      │
                      ▼ (입력 바뀔 때마다 즉시 재계산, 버튼 없음)
┌─────────────────────────────────────────────┐
│            발전량          절감액             │
│  하루      7.5 kWh    ·   약 1,600원          │
│  한 달     228 kWh    ·   약 4.9만 원         │
│  1년      2,730 kWh   ·   약 59만 원          │
│                                             │
│  손익분기  약 7~12년  (중앙 9.0년, 3,268일)    │
│  방향·그늘을 고르면 범위가 좁아져요             │
├─────────────────────────────────────────────┤
│  ⚠ 잉여가 있을 때만 표시. 예) 월 250kWh 집:     │
│    "매년 약 500kWh는 쌓이기만 하고 돈이 안 돼요. │
│     5장으로 줄여도 절감액은 거의 같아요"         │
├─────────────────────────────────────────────┤
│  ▁▂▄▆█▇▅▆▆▄▂▁  월별 발전량 막대 12개          │
├─────────────────────────────────────────────┤
│  ▸ 계산 근거 보기 (상수·가정 전부 공개, 수정 가능) │
└─────────────────────────────────────────────┘
```

첫 화면 입력은 4개(위치·패널 개수·1장 가격·월 전기요금)다. 지붕 방향·그늘은 "더 정확하게" 접힘 영역의 선택지로 두고 **기본값은 둘 다 '모름'**. 성능비·패널 W·전기 단가·보조금 같은 고급 값은 "계산 근거" 패널 안에서만 건드린다. 월 전기요금을 비워두면 단순 모드(발전량 × 230원)로 계산하고 "전기요금을 넣으면 더 정확해요" 한 줄을 띄운다. (위 숫자는 서울, 방향·그늘 모름, 월 350kWh 기준 — 3.1 검산표 4번째 줄)

## 2. 입력 / 출력 정의

### 2.1 첫 화면 입력

| 키 | 설명 | 형식 | 기본값 |
|---|---|---|---|
| `location` | 시/군/구 단위 검색 (자동완성) | 문자열 → `{lat, lon, name}` | 없음 (필수) |
| `panelCount` | 패널 장수 | 정수 1~40 | 7 (≈3 kW) |
| `pricePerPanel` | 1장당 가격(원, 설치비 포함 환산) | 정수 | 750,000 |
| `monthlyBill` | 평소 월 전기요금(원). 누진제로 사용량 역산 | 정수 | 비워둠 (선택, 강력 권장) |
| `orientation` | 지붕 방향 (접힘 영역) | `south` `flat` `eastWest` `north` `unknown` | `unknown` (모름) |
| `shade` | 그늘 (접힘 영역) | `none` `some` `heavy` `unknown` | `unknown` (모름) |

월 전기요금을 첫 화면에 두는 이유: 결과를 가장 크게 흔드는 변수다. 같은 7장이 월 150kWh 집에서는 연 28만 원, 550kWh 집에서는 연 106만 원을 아낀다(3.2). 사람들은 그늘보다 자기 전기요금을 더 잘 안다.

### 2.2 선택 입력 ("계산 근거" 패널 안)

| 키 | 설명 | 기본값 | 근거 |
|---|---|---|---|
| `panelWatt` | 패널 1장 정격(W) | 450 | 현재 주택용 보급 모듈 주류가 400~500W |
| `performanceRatio` | 성능비 PR (인버터 손실·온도·먼지·배선 손실 합산) | 0.80 (범위 0.75~0.85) | 통상 0.75~0.85 |
| `unitPrice` | 전기 단가(원/kWh). 전기요금 미입력 시에만 사용 | 230 | 아래 2.4 참고 |
| `monthlyUsage` | 월평균 사용량(kWh) 직접 입력. 요금 대신 kWh를 아는 사람용, 입력하면 `monthlyBill`보다 우선 | 비워둠 | — |
| `subsidyPerKw` | 보조금(원/kW) | 0 (토글 켜면 550,000) | 2026년 주택용 3kW 국비 kW당 55만 원 안팎으로 보도됨. 매년 고시 확인 |

### 2.3 출력

모든 출력은 낮음/중앙/높음 세 시나리오(계수·성능비의 낮은 쪽끼리, 중앙끼리, 높은 쪽끼리)로 계산한다. 화면에는 중앙값을 보여주고 손익분기는 범위로 보여준다.

| 키 | 단위 | 식 |
|---|---|---|
| `dailyKwh` · `monthlyAvgKwh` · `yearlyKwh` | kWh | **발전량.** Σ(용량 × 월별 일사량 × 일수) × 방향계수 × 그늘계수 × PR |
| `dailyWon` · `monthlyWon` · `yearlyWon` | 원 | **절감액.** 전기요금 입력 시 누진제 상계 시뮬레이션(3장), 미입력 시 발전량 × 230원 |
| `breakEvenDays` | 일 | (panelCount × pricePerPanel − 보조금) / dailyWon |
| `breakEvenRange` | [일, 일] | 높음 시나리오(빨리 회수) ~ 낮음 시나리오(늦게 회수) |
| `surplusKwh` | kWh/년 | 이월만 되고 매년 쌓이기만 하는 잉여. 0보다 크면 경고 |
| `maxUsefulPanels` | 장 | 잉여가 거의 0이 되는 최대 장수. 경고 문구에 사용 |
| `monthlyKwh[12]` | kWh/월 | 월별 차트용 |
| `lifetimeSaving` (선택) | 원 | yearlyWon × 25 − 총비용 (수명 25년, 열화 미반영) |

돈 쪽 라벨은 '수익'이 아니라 **'절감액'**이다. 10kW 이하 주택용은 상계거래라 남는 전기를 현금으로 받지 못하고, 1kWh의 가치는 "팔아서 받는 값"이 아니라 "한전에서 안 사도 되는 값"이다.

### 2.4 전기 단가 230원의 근거 (이게 오차의 최대 원천)

2026년 주택용(저압) 누진 단가는 1단계 120.0 / 2단계 214.6 / 3단계 307.3원/kWh이고, 여기에 기후환경요금 9원 + 연료비조정요금 5원이 kWh마다 붙는다.

- 태양광은 **쓰던 전기를 "위에서부터" 깎는다.** 월 350kWh 쓰던 집이 276kWh 발전하면 2단계 구간(214.6원)부터 사라진다. 그래서 1단계 단가(120원)로 계산하면 절감액을 절반 가까이 과소평가하고, 3단계(307원)로 하면 과대평가한다.
- 기본값은 **2단계 + 부가요금 ≈ 229 → 230원**. 세금(부가세 10% + 전력산업기반기금 3.7%)까지 포함하면 약 260원이지만 보수적으로 230을 쓴다.
- 월 전기요금(또는 kWh)을 입력받으면 상수를 버리고 누진제로 직접 계산한다(3장 `offsetYear`). 이때 **기본요금은 수전량 기준이라 그대로 남고 전력량요금만 줄어든다.** 잉여 발전분은 현금화되지 않고 이월되어 이후 달 사용량을 상계한다(10kW 이하 상계거래). 그래서 봄에 남은 전기가 겨울 요금을 깎는 효과까지 반영된다.

## 3. 계산 로직 (JS, 그대로 옮겨 써도 되는 수준)

아래 코드는 문서 작성 시 Node 22로 실제 실행해서 3.1·3.2의 숫자를 뽑았다.

```js
// constants.js — 전부 UI "계산 근거"에서 노출/수정 가능해야 함
export const DEFAULTS = {
  panelWatt: 450,               // W
  pr: [0.75, 0.80, 0.85],       // 성능비 [낮음, 중앙, 높음]
  unitPrice: 230,               // 원/kWh — 전기요금 미입력 시 단순 모드에서만 사용
  pricePerPanel: 750_000,       // 원, 설치비 포함 환산
  subsidyPerKw: 550_000,        // 원/kW, 2026 주택용 국비 보도치. 토글 기본 OFF
  panelLifeYears: 25,
};

// 방향 계수 — 수평면 일사량 대비. pvlib 서울 1년 시간별 시뮬레이션(Perez, 경사 30°, 평지붕은 거치대 15°)
export const ORIENTATION = {
  south:    { label: '남향',           v: [1.09, 1.09, 1.09] },
  flat:     { label: '평지붕(거치대)',  v: [1.07, 1.07, 1.07] },
  eastWest: { label: '동·서향',         v: [0.93, 0.93, 0.93] },
  north:    { label: '북향',           v: [0.75, 0.75, 0.75] },
  unknown:  { label: '모름',           v: [0.93, 1.00, 1.09] }, // 동·서향~남향 중간값
};

// 그늘 계수 — 실측 근거가 약한 경험치. UI에 그렇게 명시할 것
export const SHADE = {
  none:    { label: '거의 없음',       v: [0.95, 1.00, 1.00] },
  some:    { label: '오전/오후에 조금', v: [0.80, 0.85, 0.90] },
  heavy:   { label: '많음',           v: [0.55, 0.65, 0.75] },
  unknown: { label: '모름',           v: [0.65, 0.85, 1.00] }, // 통계 평균이 아니라 중간값
};

// 2026 주택용 저압 누진제
export const TARIFF = {
  updated: '2026-07',
  rates: [120.0, 214.6, 307.3],  // 원/kWh
  base:  [910, 1600, 7300],      // 기본요금 원
  stepsNormal: [200, 400],       // 1단계 ≤200, 2단계 ≤400, 3단계 초과
  stepsSummer: [300, 450],       // 7~8월 완화
  extraPerKwh: 9 + 5,            // 기후환경요금 + 연료비조정요금
  taxRate: 1.10 * 1.037,         // 부가세 + 전력산업기반기금
};
```

```js
// calc.js — DOM을 모르는 순수 함수
import { DEFAULTS, ORIENTATION, SHADE, TARIFF } from './constants.js';

const DAYS = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31];
const isSummer = (m) => m === 7 || m === 8;
const stepsOf = (m) => (isSummer(m) ? TARIFF.stepsSummer : TARIFF.stepsNormal);

// 전력량요금(누진) + 기후환경·연료비조정요금. 기본요금·세금 제외
export function energyCharge(kwh, month) {
  if (kwh <= 0) return 0;
  const [s1, s2] = stepsOf(month);
  const caps = [s1, s2, Infinity];
  let won = 0, prev = 0;
  for (let i = 0; i < 3 && kwh > prev; i++) {
    won += (Math.min(kwh, caps[i]) - prev) * TARIFF.rates[i];
    prev = caps[i];
  }
  return won + kwh * TARIFF.extraPerKwh;
}

// 월 청구액(원, 세금 포함)
export function bill(kwh, month = 4) {
  if (kwh <= 0) return 0;
  const [s1, s2] = stepsOf(month);
  const tier = kwh <= s1 ? 0 : kwh <= s2 ? 1 : 2;
  return (TARIFF.base[tier] + energyCharge(kwh, month)) * TARIFF.taxRate;
}

// 월 전기요금(원) → 사용량(kWh) 역산. 비여름철 요금표 기준 이분 탐색
export function usageFromBill(won) {
  if (!(won > 0)) return null;
  let lo = 0, hi = 3000;
  for (let i = 0; i < 40; i++) {
    const mid = (lo + hi) / 2;
    if (bill(mid, 4) < won) lo = mid; else hi = mid;
  }
  return Math.round((lo + hi) / 2);
}

// 상계 시뮬레이션: 잉여는 이월되어 이후 달 사용량을 상계(10kW 이하, 현금정산 없음).
// 기본요금은 수전량 기준이라 그대로 두고 전력량요금만 줄어든다.
// 정상상태를 보려고 1년을 두 번 돌리고, 두 번째 해 결과를 쓴다.
function offsetYear(usage, monthlyKwh) {
  let bank = 0, won = 0, bankAfterYear1 = 0;
  for (let pass = 0; pass < 2; pass++) {
    won = 0;
    monthlyKwh.forEach((gen, i) => {
      const m = i + 1;
      const avail = gen + bank;
      const used = Math.min(avail, usage);
      bank = avail - used;
      won += (energyCharge(usage, m) - energyCharge(usage - used, m)) * TARIFF.taxRate;
    });
    if (pass === 0) bankAfterYear1 = bank;
  }
  return { yearlyWon: won, surplusKwh: bank - bankAfterYear1 }; // 매년 쌓이기만 하는 양
}

function scenario(input, psh, k /* 0=낮음 1=중앙 2=높음 */, c) {
  const capacityKw = (input.panelCount * c.panelWatt) / 1000;
  const factor = ORIENTATION[input.orientation].v[k] * SHADE[input.shade].v[k] * c.pr[k];
  const monthlyKwh = psh.monthly.map((p, i) => capacityKw * p * factor * DAYS[i]);
  const yearlyKwh = monthlyKwh.reduce((a, b) => a + b, 0);

  const usage = input.monthlyUsage > 0 ? input.monthlyUsage : usageFromBill(input.monthlyBill);
  const { yearlyWon, surplusKwh } = usage
    ? offsetYear(usage, monthlyKwh)
    : { yearlyWon: yearlyKwh * c.unitPrice, surplusKwh: 0 };

  const subsidy = input.useSubsidy ? capacityKw * c.subsidyPerKw : 0;
  const totalCost = Math.max(input.panelCount * input.pricePerPanel - subsidy, 0);
  const dailyWon = yearlyWon / 365;
  return {
    capacityKw, usage, monthlyKwh,
    dailyKwh: yearlyKwh / 365, monthlyAvgKwh: yearlyKwh / 12, yearlyKwh,
    dailyWon, monthlyWon: yearlyWon / 12, yearlyWon,
    surplusKwh, totalCost,
    breakEvenDays: dailyWon > 0 ? totalCost / dailyWon : Infinity,
    lifetimeSaving: yearlyWon * c.panelLifeYears - totalCost,
  };
}

// 낮음/중앙/높음 세 시나리오. 손익분기 범위는 [많이 아끼는 쪽, 적게 아끼는 쪽]
export function calculate(input, psh, c = DEFAULTS) {
  const [low, mid, high] = [0, 1, 2].map((k) => scenario(input, psh, k, c));
  return { low, mid, high, breakEvenRange: [high.breakEvenDays, low.breakEvenDays] };
}

// 잉여 경고용: 중앙 시나리오에서 매년 남는 전기가 거의 0이 되는 최대 장수
export function maxUsefulPanels(input, psh, c = DEFAULTS) {
  for (let n = input.panelCount; n >= 1; n--) {
    if (scenario({ ...input, panelCount: n }, psh, 1, c).surplusKwh < 1) return n;
  }
  return 0;
}
```

| 설치 조건 | 남향 30° 대비 | 수평면 대비 (코드에 쓰는 값) |
|---|---|---|
| 남향 30° | 1.00 | 1.09 |
| 남동·남서 30° | 0.96 | 1.04 |

### 4.2 위치 검색

- **v1:** 지오코딩 API 자체가 필요 없다. `psh.json`의 키(시군구 이름)로 자동완성 검색. 초성 검색까지 넣으면 충분히 쓸 만하다.
- **v2(주소 단위):** VWorld 지오코더(국토교통부, `api.vworld.kr`) 또는 카카오 로컬 REST(`dapi.kakao.com/v2/local/search/address.json`)로 좌표 뽑고, 가장 가까운 격자값을 psh.json에서 보간. 키가 필요하므로 서버리스 프록시 하나 추가.

### 4.3 설치비·전기요금 (상수)

- 설치비: 2026년 주택용 3kW 표준 공사비 상한 약 493만 원(고시 기준 보도), 시장 견적 450~650만 원 → kW당 150~200만 원 → **450W 1장 ≈ 70~90만 원 → 기본값 75만 원**.
- 전기요금: 한전 공시 단가(2.4 참고). `constants.js` 상단에 `TARIFF_UPDATED: "2026-07"` 같은 날짜 필드를 두고 UI "계산 근거"에 표시.
- 보조금: 한국에너지공단 주택지원사업 고시. 연도별·지자체별로 달라서 **기본 OFF 토글**로 두고 금액을 사용자가 고치게 한다.

### 6.3 입력 컴포넌트

- 위치: 텍스트 입력 + 드롭다운 자동완성. 선택 후에는 칩 형태로 "경기 안산시 상록구 · 연평균 3.62 kWh/m²/일" 표시 → 사용자가 일사량 값 자체를 본다.
- 패널 개수: 슬라이더(1~40) + 숫자 입력 동기화. 옆에 "≈ 3.15 kW" 환산 표시.
- 1장당 가격: 숫자 입력, 천 단위 콤마 자동. 총액 "= 5,250,000원" 바로 아래 표시.
- 월 전기요금: 숫자 입력(원), placeholder "예: 70,000". 입력하면 아래에 "≈ 월 348kWh 사용" 역산값 표시. 비워두면 결과 옆에 "전기요금을 넣으면 더 정확해요".

### 6.5 결과 표시 규칙

- 발전량과 절감액을 한 줄에: "하루 9.6 kWh · 약 1,900원". 돈 쪽 라벨은 **'절감액'**, '수익'이라고 쓰지 않는다.

## 7. 알려진 한계 (푸터에 한 줄로 고지)

- **그늘은 실측하지 않는다.** 선택지 계수(경험치)로만 반영한다. 주변 건물 그늘 자동 계산은 v2. 구글 Solar API는 한국 미지원으로 보인다(2026-05 릴리스 노트의 데이터 확장 국가 목록에 한국 없음, 2026-02 정밀지도 반출 허가에서 3D 높이 정보 제외). 서울·도쿄 좌표로 대조하면 확인할 수 있다.

```bash
KEY=발급받은_키   # Cloud 콘솔에서 Solar API 사용 설정 필요
# 서울시청
curl -s "https://solar.googleapis.com/v1/buildingInsights:findClosest?location.latitude=37.5663&location.longitude=126.9779&requiredQuality=LOW&key=$KEY" | head -c 300; echo
# 대조군: 도쿄역
curl -s "https://solar.googleapis.com/v1/buildingInsights:findClosest?location.latitude=35.6812&location.longitude=139.7671&requiredQuality=LOW&key=$KEY" | head -c 300; echo
```

- 방향 계수는 pvlib 근사(가정 월별 일사량 + Erbs 분리)라 정밀값이 아니다.
- 패널 열화(연 0.5%), 인버터 교체비(10~15년에 1회, 수십만 원), 전기요금 인상률은 미반영. 열화·교체비를 빼고 계산했으므로 실제 손익분기는 이보다 조금 길어질 수 있다.
- 10kW 이하 상계거래는 잉여전력 현금정산이 안 된다(한전). 사용량보다 많이 설치하면 발전량은 늘어도 절감액은 늘지 않는다 — `surplusKwh` 경고로 표시한다.
- 월 전기요금 역산은 비여름철 요금표 기준이고, 그 사용량을 12개월에 똑같이 적용한다. 계절별 사용량 차이는 미반영(v1.1).
- 세금 처리 단순화: 줄어든 전력량요금에 부가세·기금 세율을 그대로 곱한다.

푸터 문구: "주변 건물 그늘은 반영하지 않은 추정치예요. 정확한 값은 현장 실사가 필요해요."
