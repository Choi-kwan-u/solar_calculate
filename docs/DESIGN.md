# 태양광 손익분기 계산기 — 기획/설계 문서

> 위치 검색 → 패널 개수·1장 가격·월 전기요금 입력 → 하루/한 달/1년 발전량(kWh)·절감액(원)과 손익분기 일수(범위)를 한 화면에서 바로 보여주는 정적 웹사이트.
> 광고·회원가입·수익화 없음. 계산기 하나로 끝나는 사이트.

**v2.1 (2026-10-21)** — 코드에 맞춰 고침: 세금 계수 1.127(부가세 + 전력기금 2.7%, 합), 보조금은 총액 입력(비우면 국비 3kW 추정), NASA POWER 2001–2025·1° 격자, 검산표를 새 상수로 다시 뽑음, 지상 실측 비교(4.1, [VALIDATION.md](VALIDATION.md)) 추가. 코드는 이 문서에 복사하지 않고 `src/`가 원본이다(3장).

## 0. 결론 먼저

| 질문 | 답 |
|---|---|
| LLM 필요한가? | **아니오.** 입력이 전부 구조화된 값(숫자·선택지)이고 출력은 사칙연산 결과라 결정론적 계산이면 충분하다. LLM을 끼우면 비용·지연·비결정성(같은 입력에 다른 숫자)·숫자 환각만 생긴다. |
| 그럼 쉬운 프로젝트인가? | 계산식 자체는 쉽다. **어려운 건 데이터 쪽 세 가지**: ① 위치→일사량 매핑, ② 전기요금이 누진제라 "kWh당 단가"가 상수가 아님, ③ 패널 와트수·방향·성능비 같은 가정이 결과를 ±20% 흔든다. |
| 설계 원칙 | 모든 상수를 화면에 드러내고(접이식 "계산 근거" 패널) 사용자가 바꿀 수 있게 한다. 숫자가 틀려 보여도 "왜 그렇게 나왔는지"가 보이면 신뢰가 유지된다. |
| 결과 숫자의 의미 | **발전량(kWh)과 절감액(원)을 나란히 보여준다.** 발전량은 위치·패널·방향·그늘로 정해지는 물리량이고, 돈은 '수익'이 아니라 '절감액'이다. 10kW 이하 주택용은 상계거래라 남는 전기를 현금으로 받지 못한다. |
| 결과를 가장 크게 흔드는 변수 | **그 집의 전기 사용량.** 같은 패널 7장이 월 150kWh 집에서는 손익분기 19년, 550kWh 집에서는 5년(3.2). 그늘(±15~35%)보다 훨씬 크다 → 월 전기요금 입력을 첫 화면에 둔다. 보조금도 크다 — 지자체 지원까지 받으면 자부담이 설치비의 20% 수준까지 내려간다(2.2). |
| 위치는 얼마나 중요한가 | **생각보다 덜하다.** 위성 일사량 격자가 약 100km(1°)라 원래는 256개 시군구가 20개 값으로 뭉쳤고, 기상청 실측 보정 후에도 연평균이 3.50~4.21 kWh/m²/일(±9%)이다. 사용량(최대 4배)보다 훨씬 작다. 화면엔 "위성 자료를 가까운 관측소 실측에 맞춘 값"이라고 적어 정밀한 척하지 않는다. |
| 그늘·방향을 모르는 사용자 | "없음"이 아니라 **"모름"을 기본 선택**으로 둔다. "없음"은 최선값이라 모르는 사람이 누르면 손익분기가 짧게 찍힌다. "모름"은 중간값 + 넓은 범위. |

## 1. 사용자 흐름

```
[위치 검색]    "서울 중구"  ──▶ 일사량 조회(연평균 + 월별 12개)
[패널 개수]    7장 (슬라이더 1~40)
[1장당 가격]   750,000원 (기본값 채워져 있고 수정 가능)
[월 전기요금]  70,650원 (선택·강력 권장) ──▶ "≈ 월 350kWh 사용" 역산 표시
 ▸ 더 정확하게:  지붕 방향 [모름|남|동·서|북|평지붕]   그늘 [모름|없음|조금|많음]
                      │
                      ▼ (입력 바뀔 때마다 즉시 재계산, 버튼 없음)
┌─────────────────────────────────────────────┐
│            발전량          절감액             │
│  하루      7.7 kWh    ·   약 1,600원          │
│  한 달     233 kWh    ·   약 4.9만 원         │
│  1년      2,800 kWh   ·   약 59만 원          │
│                                             │
│  손익분기  약 7~12년  (중앙 8.9년, 3,247일)    │
│  방향·그늘을 고르면 범위가 좁아져요             │
├─────────────────────────────────────────────┤
│  ⚠ 잉여가 있을 때만 표시. 예) 월 250kWh 집:     │
│    "매년 약 500kWh는 쌓이기만 하고 돈이 안 돼요. │
│     5장으로 줄여도 절감액은 거의 같아요"         │
├─────────────────────────────────────────────┤
│  ▁▂▄▆█▇▅▆▆▄▂▁  월별 발전량 막대 12개          │
├─────────────────────────────────────────────┤
│  ▸ 계산 근거 보기 (상수·가정 전부 공개, 수정 가능) │
└─────────────────────────────────────────────┘
```

첫 화면 입력은 4개(위치·패널 개수·1장 가격·월 전기요금)다. 지붕 방향·그늘은 "더 정확하게" 접힘 영역의 선택지로 두고 **기본값은 둘 다 '모름'**. 성능비·패널 W·전기 단가·보조금 같은 고급 값은 "계산 근거" 패널 안에서만 건드린다. 월 전기요금을 비워두면 단순 모드(발전량 × 230원)로 계산하고 "전기요금을 넣으면 더 정확해요" 한 줄을 띄운다. (위 숫자는 서울 중구 실제 일사량(NASA × ASOS 보정), 방향·그늘 모름, 월 350kWh 기준 — 3.1 검산표 5번째 줄. 사이트가 실제로 보여 주는 값이다.)

## 2. 입력 / 출력 정의

### 2.1 첫 화면 입력

| 키 | 설명 | 형식 | 기본값 |
|---|---|---|---|
| `location` | 시/군/구 단위 검색 (자동완성) | 문자열 → `{lat, lon, name}` | 없음 (필수) |
| `panelCount` | 패널 장수 | 정수 1~40 | 7 (≈3 kW) |
| `pricePerPanel` | 1장당 가격(원, 설치비 포함 환산) | 정수 | 750,000 |
| `monthlyBill` | 평소 월 전기요금(원). 누진제로 사용량 역산 | 정수 | 비워둠 (선택, 강력 권장) |
| `orientation` | 지붕 방향 (접힘 영역) | `south` `flat` `eastWest` `north` `unknown` | `unknown` (모름) |
| `shade` | 그늘 (접힘 영역) | `none` `some` `heavy` `unknown` | `unknown` (모름) |

월 전기요금을 첫 화면에 두는 이유: 결과를 가장 크게 흔드는 변수다. 같은 7장이 월 150kWh 집에서는 연 27만 원, 550kWh 집에서는 연 105만 원을 아낀다(3.2). 사람들은 그늘보다 자기 전기요금을 더 잘 안다.

### 2.2 선택 입력 ("계산 근거" 패널 안)

| 키 | 설명 | 기본값 | 근거 |
|---|---|---|---|
| `panelWatt` | 패널 1장 정격(W) | 450 | 현재 주택용 보급 모듈 주류가 400~500W |
| `performanceRatio` | 성능비 PR (인버터 손실·온도·먼지·배선 손실 합산). 중앙값만 편집, 낮음·높음은 ±0.05 | 0.80 (범위 0.75~0.85) | 통상 0.75~0.85 |
| `unitPrice` | 전기 단가(원/kWh). 전기요금 미입력 시에만 사용 | 230 | 아래 2.4 참고 |
| `monthlyUsage` | 월평균 사용량(kWh) 직접 입력. 요금 대신 kWh를 아는 사람용, 입력하면 `monthlyBill`보다 우선 | 비워둠 | — |
| `useSubsidy` · `subsidyTotal` | 보조금 적용 여부와 **총액(원)** — 국비 + 시·도비 + 시·군·구비. 비워두면 국비만 추정: min(용량, 3kW) × kW당 55만 원 | 끔 · 비워둠 | 주택지원사업 태양광 지원범위는 3kW 이하/세대, 2026 국비 3kW 165만 원(kW당 55만 원) 사례. 같은 사례에서 도비 60만 + 군비 140만까지 총 365만 원이 지원돼 3kW 454만 원 설치 자부담이 89만 원이었다 — 국비만 넣으면 그런 집의 손익분기가 실제보다 훨씬 길게 나오므로 총액으로 받는다 |

### 2.3 출력

모든 출력은 낮음/중앙/높음 세 시나리오(계수·성능비의 낮은 쪽끼리, 중앙끼리, 높은 쪽끼리)로 계산한다. 화면에는 중앙값을 보여주고 손익분기는 범위로 보여준다.

| 키 | 단위 | 식 |
|---|---|---|
| `dailyKwh` · `monthlyAvgKwh` · `yearlyKwh` | kWh | **발전량.** Σ(용량 × 월별 일사량 × 일수) × 방향계수 × 그늘계수 × PR |
| `dailyWon` · `monthlyWon` · `yearlyWon` | 원 | **절감액.** 전기요금 입력 시 누진제 상계 시뮬레이션(3장), 미입력 시 발전량 × 230원 |
| `breakEvenDays` | 일 | (panelCount × pricePerPanel − 보조금) / dailyWon |
| `breakEvenRange` | [일, 일] | 높음 시나리오(빨리 회수) ~ 낮음 시나리오(늦게 회수) |
| `surplusKwh` | kWh/년 | 이월만 되고 매년 쌓이기만 하는 잉여. 1kWh 이상이면 경고 |
| `maxUsefulPanels` | 장 | 잉여가 거의 0이 되는 최대 장수. 경고 문구와 "N장으로 바꿔 보기" 버튼에 사용 |
| `monthlyKwh[12]` | kWh/월 | 월별 차트용 |
| `lifetimeSaving` (선택) | 원 | yearlyWon × 25 − 총비용 (수명 25년, 열화 미반영) |

돈 쪽 라벨은 '수익'이 아니라 **'절감액'**이다. 10kW 이하 주택용은 상계거래라 남는 전기를 현금으로 받지 못하고, 1kWh의 가치는 "팔아서 받는 값"이 아니라 "한전에서 안 사도 되는 값"이다.

### 2.4 전기 단가 230원의 근거 (이게 오차의 최대 원천)

2026년 주택용(저압) 누진 단가는 1단계 120.0 / 2단계 214.6 / 3단계 307.3원/kWh이고, 여기에 기후환경요금 9원 + 연료비조정요금 5원이 kWh마다 붙는다.

- 태양광은 **쓰던 전기를 "위에서부터" 깎는다.** 월 350kWh 쓰던 집이 276kWh 발전하면 2단계 구간(214.6원)부터 사라진다. 그래서 1단계 단가(120원)로 계산하면 절감액을 절반 가까이 과소평가하고, 3단계(307원)로 하면 과대평가한다.
- 기본값은 **2단계 + 부가요금 ≈ 229 → 230원**. 세금(부가세 10% + 전력산업기반기금 2.7%, 둘 다 전기요금계에 붙으니 합쳐 ×1.127)까지 포함하면 약 258원이지만 보수적으로 230을 쓴다.
- 월 전기요금(또는 kWh)을 입력받으면 상수를 버리고 누진제로 직접 계산한다(3장 상계 시뮬레이션). 이때 **기본요금은 수전량 기준이라 그대로 남고 전력량요금만 줄어든다.** 잉여 발전분은 현금화되지 않고 이월되어 이후 달 사용량을 상계한다(10kW 이하 상계거래). 그래서 봄에 남은 전기가 겨울 요금을 깎는 효과까지 반영된다.

## 3. 계산 로직

**코드는 `src/constants.js`(상수)와 `src/calc.js`(계산)가 원본이다.** 이 문서에 복사하지 않는다 — 복사본은 반드시 어긋난다. 대신 아래 3.1·3.2 표의 숫자를 `tests/calc.test.js`가 그대로 검사하므로, 상수나 식을 바꾸면 테스트가 깨지고 그때 표를 다시 뽑아 문서와 테스트를 같이 고친다.

### 3.0 상수와 계산 순서

| 상수 | 값 | 비고 |
|---|---|---|
| 패널 정격 · 성능비 | 450W · [0.75, 0.80, 0.85] | 성능비는 [낮음, 중앙, 높음] |
| 전기 단가(단순 모드) | 230원/kWh | 2단계 214.6 + 기후환경 9 + 연료비조정 5 |
| 1장 가격 · 수명 | 750,000원 · 25년 | |
| 국비 추정 | kW당 550,000원, 세대당 3kW까지 | 보조금 총액을 비웠을 때만 |
| 누진 단가 · 기본요금 | 120.0 / 214.6 / 307.3원/kWh · 910 / 1,600 / 7,300원 | 한전 주택용 저압 2026-07 |
| 누진 구간 | ≤200 / ≤400kWh, 7~8월 ≤300 / ≤450kWh | |
| 부가요금 | 기후환경 9 + 연료비조정 5원/kWh | |
| 세금 | × (1 + 0.10 + 0.027) = 1.127 | 부가세 10% + 전력산업기반기금 2.7%(3.7% → 3.2% 2024-07 → 2.7% 2025-07) |
| 방향 계수 [낮음, 중앙, 높음] | 남향 1.09 · 평지붕(거치대) 1.07 · 동·서향 0.93 · 북향 0.75 · 모름 [0.93, 1.00, 1.09] | 3.3 |
| 그늘 계수 [낮음, 중앙, 높음] | 없음 [0.95, 1.00, 1.00] · 조금 [0.80, 0.85, 0.90] · 많음 [0.55, 0.65, 0.75] · 모름 [0.65, 0.85, 1.00] | 경험치, 3.3 |

1. 용량 = 장수 × W ÷ 1000. 월 발전량 = 용량 × 월 일사량 × 일수 × 방향 × 그늘 × PR — 낮음/중앙/높음 각각.
2. 사용량 = 직접 넣은 kWh, 없으면 월 전기요금을 비여름철 요금표로 역산(0~3000kWh 이분 탐색). 둘 다 없으면 단순 모드.
3. 절감액(사용량을 알 때) = 상계 시뮬레이션. 매달 (발전량 + 이월분)으로 사용량을 상계하고 남으면 이월한다. 줄어드는 건 전력량요금(누진) + 기후환경·연료비조정요금이고, 기본요금은 그대로, 줄어든 금액에 세금 1.127을 곱한다. 정상상태를 보려고 1년을 두 번 돌려 둘째 해를 쓴다. 단순 모드면 발전량 × 230원.
4. 보조금 = 직접 넣은 총액, 없으면 국비 추정. 설치비를 넘지 않는다. 자부담 = 설치비 − 보조금.
5. 손익분기 = 자부담 ÷ 하루 절감액. 범위 = [높음 시나리오, 낮음 시나리오].
6. 잉여 = 둘째 해 말 이월 잔량 − 첫째 해 말 잔량(매년 쌓이기만 하는 양). 적정 장수 = 중앙 시나리오에서 잉여가 1kWh 미만이 되는 최대 장수.

### 3.1 검산 (이 숫자 안 나오면 식이 틀린 것)

입력 공통: 450W × 7장(3.15kW), 1장 75만 원. 1~4번 줄은 서울 가정 일사량(월별 `[2.1, 2.9, 3.8, 4.6, 5.0, 4.6, 3.6, 3.9, 3.8, 3.3, 2.4, 1.9]`, 연평균 ≈3.49), 5번 줄은 사이트가 쓰는 서울 중구 실제 일사량(NASA 3.90 × ASOS 보정 0.918 = 연평균 3.58).

| 케이스 | 발전량 (하루 / 월 / 년) | 절감액 (하루 / 월 / 년) | 손익분기 중앙 (범위) |
|---|---|---|---|
| 남향·그늘 없음, 요금 미입력(×230원) | 9.6 / 292 / 3,502 kWh | 2,207 / 67,114 / 805,373원 | 2,379일 = 6.5년 (6.1~7.3년) |
| 남향·그늘 없음, 월 350kWh | 9.6 / 292 / 3,502 kWh | 1,916 / 58,283 / 699,390원 | 2,740일 = 7.5년 (7.2~8.2년) |
| 위와 같음 + 보조금(국비 추정 165만 원) | 〃 | 〃 | 1,879일 = 5.1년 (4.9~5.6년) |
| 방향·그늘 모름, 월 350kWh | 7.5 / 228 / 2,731 kWh | 1,587 / 48,274 / 579,289원 | 3,308일 = 9.1년 (7.2~12.4년) |
| 서울 중구 실제 일사량(보정 후 3.58), 방향·그늘 모름, 월 350kWh | 7.7 / 233 / 2,800 kWh | 1,617 / 49,186 / 590,231원 | 3,247일 = 8.9년 (7.0~12.2년) |

- 월 292kWh는 시중 자료의 "중부 3kW 월 270~320kWh" 범위 안이다.
- 요금 미입력 모드(230원)가 월 350kWh 정밀 모드보다 절감액을 약 15% 높게 잡는다. 실제로는 발전량 일부가 1단계(120원) 구간까지 깎아 내려가기 때문이다. 전기요금 입력을 권장하는 근거.
- 국비만 받은 5.1년은 업계가 말하는 "4~5년 회수"가 보조금 포함 기준이라는 점과 대체로 맞는다. 지자체 보조금까지 받으면 더 짧아진다(2.2).
- **실제 사이트 숫자는 1~4번 줄과 비슷하다.** 보정 전 NASA 값(서울 3.90)은 가정값 3.49보다 12% 높았지만, ASOS 실측으로 보정하면 서울 3.58이 돼 가정값과 3% 차이다(4번 → 5번 줄: 2,731 → 2,800kWh). 전국 시군구 값은 보정 후 3.50~4.21.
- `usageFromBill(71000)` = 351kWh, `usageFromBill(70650)` = 350kWh, `bill(350)` = 70,652원.

### 3.3 방향·그늘 계수 근거

pvlib(Perez 모델)로 서울(37.57°N, 126.98°E) 1년 시간별 시뮬레이션. 월별 일사량은 3.1의 가정값, 직달·산란 분리는 Erbs 경험식.

| 설치 조건 | 남향 30° 대비 | 수평면 대비 (코드에 쓰는 값) |
|---|---|---|
| 남향 30° | 1.00 | 1.09 |
| 남동·남서 30° | 0.96 | 1.04 |
| 동·서향 30° | 0.85 | 0.93 |
| 북향 30° | 0.69 | 0.75 |
| 평지붕, 거치대로 남향 15° | 0.98 | 1.07 |
| 평지붕, 그냥 눕혀서 | 0.92 | 1.00 |

- 일사량 데이터가 수평면 값이라 오른쪽 열을 곱한다. 남향 대비 값을 곱하면 남향 집도 9% 손해 보는 걸로 나온다.
- 국내 옥상은 대부분 거치대로 남향 경사를 주므로 평지붕은 1.07로 보고, 눕혀 설치는 선택지에서 뺐다. 남동·남서는 남향으로 골라도 오차 5% 이내라 따로 두지 않았다.
- 근사 계산이라 소수점 둘째 자리까지 믿을 값은 아니지만, 방향 간 비율은 입력값에 크게 흔들리지 않는다.
- 그늘 계수(1.00 / 0.85 / 0.65)는 이런 일반 시뮬레이션으로 검증할 수 없는 **경험치**다. 그래서 범위를 방향보다 넓게 잡았다.
- "모름"은 통계 평균이 아니라 선택지들의 **중간값**이다(한국 주택의 방향·그늘 분포 통계가 없음). 방향 모름 1.00은 수평면 데이터를 그대로 쓰는 것과 같다.

## 4. 데이터 소스

### 4.1 일사량 (핵심)

| 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **NASA POWER API** `https://power.larc.nasa.gov/api/temporal/climatology/point?parameters=ALLSKY_SFC_SW_DWN&community=RE&longitude={lon}&latitude={lat}&format=JSON` | 키 없음, 위경도 아무 점이나 됨, 월별 12개 + 연평균을 kWh/m²/day로 바로 줌 (= PSH). 기후값 기간 2001–2025(25년) | 태양 값은 CERES SYN1deg **1°×1° 격자(약 100km)** — 기상 값만 MERRA-2 ½°×⅝°. 그래서 256개 시군구가 20개 값으로 뭉친다. 국내 공공데이터 아님 | **v1 채택.** 정적 테이블 생성용 |
| 기상자료개방포털 기상자원지도 (평균 수평면/경사면 일사량) `data.kma.go.kr` | 국내 공식, 경사면 값도 있음 | API가 아니라 자료 내려받기 성격, 전처리 필요 | v3 교체 후보. 아래 비교 결과를 보고 결정 |
| 공공데이터포털 "기상청_지상(종관, ASOS) 일자료 조회서비스" `data.go.kr` | 관측소 실측 일사(MJ/m²) | 일사계 있는 관측소만 가능, 다년 평균 직접 내야 함, MJ→kWh 변환(÷3.6), 서비스 키 필요, CORS 안 됨 | 검증용 — 다음 단계 |

**핵심 결정: 일사량은 런타임에 호출하지 않는다.**
기후값은 안 바뀌니까 빌드 시점에 전국 시군구 256곳의 대표 좌표로 NASA POWER를 한 번씩 돌려 `data/psh.json`을 만들어 사이트에 박아 넣는다. 결과: 키 유출 없음, CORS 문제 없음, 응답 즉시, 백엔드 0.

- 대표 좌표: `scripts/build-regions.mjs`가 행정동 경계([vuski/admdongkor](https://github.com/vuski/admdongkor), 2026-10-01판)를 시군구로 묶어 면적 중심을 낸다. 섬 지역처럼 중심이 바깥이면 가장 큰 폴리곤 안쪽 점으로 옮긴다 → `data/regions.json`.
- 일사량: `scripts/build-psh.mjs`가 256회 호출(동시 4개, 응답 캐시) → `data/psh.json`.

```json
// data/psh.json
{
  "meta": { "source": "NASA POWER", "dataset": "SYN1DEG", "period": "2001–2025", "surface": "수평면",
            "distinctCells": 20, "regions": { "asOf": "2026-10-01", "count": 256, ... }, ... },
  "regions": {
    "경기 안산시 상록구": { "code": "41271", "lat": 37.3152, "lon": 126.8706, "annual": 3.9,
      "monthly": [2.42, 3.2, 4.3, 5.02, 5.56, 5.25, 4.21, 4.5, 4.18, 3.59, 2.44, 2.11],
      "aliases": ["경기도 안산시 상록구"] },
    ...
  }
}
```

**지상 실측으로 보정** ([VALIDATION.md](VALIDATION.md)): 기상청 ASOS 22개 지점 2001~2025 일자료와 비교하면 NASA 값은 평균 +1%지만 수도권이 높고(서울 +9%, 인천·수원 +5%) 남해안이 낮았다(부산 −5%, 광주·대전·창원 −4%). 그래서 시군구마다 가까운 3개 지점의 "실측÷NASA" 비율을 거리 역제곱 가중 평균해 월별 값에 곱한다(`scripts/correct-psh.mjs`, 계수 0.92~1.05). 원본 NASA 값은 psh.json에 `nasa`로 남긴다. 보정 후 지점 기준 차이는 0%, 전국 값은 3.50~4.21(서로 다른 값 230개).

### 4.2 위치 검색

- **v1:** 지오코딩 API 자체가 필요 없다. `psh.json`의 키(시군구 이름)로 자동완성 검색. 띄어쓰기 무시, 초성(ㅇㅅ → 안산), 조합 중인 글자(상로 → 상록), 단어 건너뛰기(경기 상록), 옛 이름(광주 북구 → 전남광주 북구, 인천 서구 → 서해구·검단구, 강원도 …)까지 찾는다. 전남광주통합특별시는 공식 약칭이 확정 전이라 "전남광주"로 표시.
- **v2(주소 단위):** VWorld 지오코더(국토교통부, `api.vworld.kr`) 또는 카카오 로컬 REST(`dapi.kakao.com/v2/local/search/address.json`)로 좌표 뽑고, 가장 가까운 격자값을 psh.json에서 보간. 키가 필요하므로 서버리스 프록시 하나 추가. 단 격자가 100km라 주소 단위로 바꿔도 일사량은 거의 안 달라진다 — 그늘 자동 계산과 묶을 때 의미가 있다.

### 4.3 설치비·전기요금·보조금 (상수)

- 설치비: 2026년 주택용 3kW 표준 공사비 상한 약 493만 원(고시 기준 보도), 시장 견적 450~650만 원 → kW당 150~200만 원 → **450W 1장 ≈ 70~90만 원 → 기본값 75만 원**.
- 전기요금: 한전 공시 단가(2.4 참고). `TARIFF.updated: "2026-07"`을 UI "계산 근거"에 표시. 2026년 3분기 동결, 4분기 미확인.
- 보조금: 한국에너지공단 주택지원사업(국비) + 시·도·시군구 지원. 연도별·지자체별로 달라서 **총액을 사용자가 넣게** 하고, 비우면 국비만 추정한다. 기본 OFF.

| 애니메이션 | 숫자 전환만 200ms (count-up 금지, 그냥 페이드). 나머지 없음. `prefers-reduced-motion`이면 끔 |

### 6.3 입력 컴포넌트

- 위치: 텍스트 입력 + 드롭다운 자동완성. 선택 후에는 칩 형태로 "경기 안산시 상록구 · 연평균 3.90 kWh/m²/일" 표시 → 사용자가 일사량 값 자체를 본다. 칩 아래에 "일사량은 위성 자료의 약 100km 격자 평균이라 가까운 시군구끼리는 값이 같아요" 한 줄.
- 패널 개수: 슬라이더(1~40) + 숫자 입력 동기화. 옆에 "≈ 3.15 kW" 환산 표시.
- 1장당 가격: 숫자 입력, 천 단위 콤마 자동. 총액 "= 5,250,000원" 바로 아래 표시. 보조금을 켜면 "· 보조금 빼면 자부담 3,600,000원"을 붙인다.
- 월 전기요금: 숫자 입력(원), placeholder "예: 70,000". 입력하면 아래에 "≈ 월 350kWh 사용" 역산값 표시. 비워두면 결과 옆에 "전기요금을 넣으면 더 정확해요".
- 지붕 방향·그늘: "더 정확하게" 접힘 영역 안의 세그먼트 버튼. 기본 선택은 둘 다 **모름**. "없음"을 기본값으로 두지 않는다 — 최선값이 평균처럼 보여 손익분기가 짧게 찍힌다.

### 6.4 "계산 근거" 패널 (접힘)

열면 아래가 전부 **편집 가능한 필드**로 나온다.

```
패널 1장 정격        [450] W
성능비(PR)           [0.80]   범위 0.75~0.85
전기 단가            [230] 원/kWh   ⓘ 전기요금 미입력 시에만 사용(2단계 기준)
월평균 사용량        [    ] kWh (선택, 요금 대신 직접 입력)
보조금 적용          [ ] 총 [1,650,000] 원   ⓘ 비우면 국비만: 3kW × 55만 원. 시·도·군 보조금도 받으면 합친 금액
지붕 방향 계수        남향 1.09 · 평지붕(거치대) 1.07 · 동·서향 0.93 · 북향 0.75 · 모름 1.00(0.93~1.09)
                     ⓘ 수평면 일사량 대비. pvlib 서울 시뮬레이션 기준
그늘 계수            없음 1.00(0.95~1.00) · 조금 0.85(0.80~0.90) · 많음 0.65(0.55~0.75) · 모름 0.85(0.65~1.00)
                     ⓘ 실측 근거가 약한 경험치. '모름'은 통계 평균이 아니라 중간값
일사량 출처          NASA POWER 2001–2025 기후값 · 수평면 · 약 100km 격자
                     ⓘ 기상청 ASOS 22개 지점 2001~2025 실측 비율로 보정(가까운 3곳 거리 가중)
요금표 기준          한전 주택용 저압 2026-07 · 부가세 10% + 전력기금 2.7%
지역 좌표            행정동 경계 2026-10-01 기준 시군구 256곳의 중심점
```

그 아래 "지금 숫자가 나온 과정"으로 용량 → 연 발전량 → 사용량 → 절감액 → 자부담 → 손익분기 → 범위 → 25년 누적을 실제 숫자로 풀어 보여 준다. 이 패널이 있어서 "그 숫자 어디서 나왔냐"에 답이 된다. 숨기면 계산기가 아니라 광고처럼 보인다.

### 6.5 결과 표시 규칙

- 발전량과 절감액을 한 줄에: "하루 8.4 kWh · 약 1,700원". 돈은 유효숫자 2자리 + "약", 1만 원부터 만 원 단위. 돈 쪽 라벨은 **'절감액'**, '수익'이라고 쓰지 않는다.
- 손익분기는 범위를 크게, 중앙값은 작게: "약 7~8년 (중앙 7.5년, 2,740일)". 범위는 정수 년으로 반올림하고, 같아지면 "약 7년".
- 방향·그늘이 '모름'이라 범위가 넓으면(반올림한 두 끝이 다르면) 아래에 "방향·그늘을 고르면 범위가 좁아져요" 한 줄.
- 중앙값이 패널 수명(25년)을 넘으면 "패널 수명 안에 본전을 찾기 어려워요" 한 줄.
- `surplusKwh ≥ 1`이면 경고 카드: "매년 약 {surplusKwh}kWh는 쌓이기만 하고 돈이 안 돼요. {maxUsefulPanels}장으로 줄여도 절감액은 거의 같아요." + "{maxUsefulPanels}장으로 바꿔 보기" 버튼.

## 7. 알려진 한계 (푸터에 한 줄로 고지)

- **그늘은 실측하지 않는다.** 선택지 계수(경험치)로만 반영한다. 주변 건물 그늘 자동 계산은 v2. 구글 Solar API는 한국 미지원으로 보인다(2026-05 릴리스 노트의 데이터 확장 국가 목록에 한국 없음, 2026-02 정밀지도 반출 허가에서 3D 높이 정보 제외). 서울·도쿄 좌표로 대조하면 확인할 수 있다.

```bash
KEY=발급받은_키   # Cloud 콘솔에서 Solar API 사용 설정 필요
# 서울시청
curl -s "https://solar.googleapis.com/v1/buildingInsights:findClosest?location.latitude=37.5663&location.longitude=126.9779&requiredQuality=LOW&key=$KEY" | head -c 300; echo
# 대조군: 도쿄역
curl -s "https://solar.googleapis.com/v1/buildingInsights:findClosest?location.latitude=35.6812&location.longitude=139.7671&requiredQuality=LOW&key=$KEY" | head -c 300; echo
```

- **일사량은 약 100km 격자 위성 추정치를 관측소 22곳 실측에 맞춰 보정한 값이다.** 관측소 사이 지역은 거리 가중 보간이라 오차가 남는다(4.1).
- 방향 계수는 pvlib 근사(가정 월별 일사량 + Erbs 분리)라 정밀값이 아니다.
- 패널 열화(연 0.5%), 인버터 교체비(10~15년에 1회, 수십만 원), 전기요금 인상률은 미반영. 열화·교체비를 빼고 계산했으므로 실제 손익분기는 이보다 조금 길어질 수 있다.
- 10kW 이하 상계거래는 잉여전력 현금정산이 안 된다(한전). 사용량보다 많이 설치하면 발전량은 늘어도 절감액은 늘지 않는다 — `surplusKwh` 경고로 표시한다.
- 월 전기요금 역산은 비여름철 요금표 기준이고, 그 사용량을 12개월에 똑같이 적용한다. 계절별 사용량 차이는 미반영(v1.1).
- 세금 처리 단순화: 줄어든 전력량요금에 부가세·기금 세율을 그대로 곱한다.

푸터 문구: "주변 건물 그늘은 반영하지 않은 추정치예요. 정확한 값은 현장 실사가 필요해요."
